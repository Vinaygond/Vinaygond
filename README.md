## Now building: Exit Protocol

[Exit Protocol](https://exitprotocols.com) is forensic litigation intelligence for high-conflict divorce, asset tracing, and financial discovery.

```
selected financial records → deterministic LIBR tracing → attorney-reviewable workpaper
  → source provenance → SHA-256 snapshot integrity
```

The platform turns messy bank statements and discovery documents into structured, **attorney-reviewable** evidence. AI accelerates document understanding; deterministic engines handle the legal math. Outputs are structured review material for counsel and retained experts — not legal advice, expert opinion, or court filings.

| System | What it does |
|---|---|
| **LIBR Tracing Engine** | Deterministic Lowest Intermediate Balance Rule workpapers for commingled asset analysis |
| **Document Ingestion** | OCR-assisted extraction from PDFs, statements, and transaction exports |
| **Evidence Integrity** | SHA-256 snapshot sealing, source provenance, and reviewable processing history |
| **Sovereign Deployment** | Containerized, private infrastructure for sensitive legal and financial data |

## Founder arc: speed → constraints → defensible systems

**Hydra / XLeadScraper** was my first major venture: a distributed data infrastructure product that reached roughly **$500k ARR in six months** and processed **millions of requests per day** at peak.

It proved I could build and sell. It also proved that **throughput alone is not architecture** — systems serving real customers must treat platform, legal, and customer-risk boundaries as design requirements, not afterthoughts.

After a compliance reset in late 2024, I rebuilt around one principle:

> **Constraints are part of the architecture.**

That pivot now shapes everything I ship — including Exit Protocol, where deterministic calculations, clear data boundaries, and reviewable evidence trails are product requirements from day one.

## How I build

- Use AI where it accelerates judgment — not where determinism is required
- Treat legal, platform, data, and security constraints as architecture inputs
- Prefer boring, proven infrastructure until the problem earns complexity
- Build for revenue, reliability, and long-term trust at the same time
- Ship reviewable artifacts, not black-box claims
